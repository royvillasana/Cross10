- [x] 1.2 **Undo writes into the wrong layer when the selection has moved.** *No longer destructive; still not fully correct, and the code says which. The sync now separates "the author moved a control" from "the runtime moved history" using the undo/redo stack depths, and refuses to fold when the reverted values belong to a layer other than the one selected. Undoing your own last edit on the layer you are looking at still works. Undoing an edit made on a layer you have since left is now inert rather than corrupting: the runtime reverted controls that no longer describe the layer the patch belonged to, and the product cannot be told which layer that was. A reverted patch does not say which layer it belonged to, and the record follows the controls (R56). Undo is correct for the layer you are on. The real fix is the record becoming the single store rather than a follower, which is an amendment to R56 rather than a patch to the sync

## 1a. Gaps the spec audit found

Each is a requirement the specs state and the app does not meet. They are listed
here as they are found, so 1.1 produces work rather than only verdicts.

- [ ] 1a.1 **Difference and additive blend modes are missing** (`interference-layer`). The spec requires normal, multiply, screen, difference and additive; the app ships normal, multiply, screen and overlay. Two scenarios cannot pass: the absolute per-channel difference reading, and red-over-green rendering yellow. Additive in particular is not decoration — *Couleur Additive* is one of the techniques this product is named for, the gallery has entries claiming it, and the `stripe-engines` audit found that **Transchromie cannot be rendered as specified without it**: overlapping translucent planes with selectable subtractive *and additive* blending is what that technique is

- [ ] 1a.2 **Randomize with locks is not built** (`scene-presets`). No randomize command, no lock switches. The spec's design reasoning is sound and worth keeping — why the command and its locks live in one section rather than the sticky footer — so what is missing is the building, not the deciding

- [ ] 1a.3 **Decide whether `post-fx-suite` belongs to this product at all.** Five requirements, none built, nothing depending on them. They describe a general creative-coding toolkit — ASCII output, datamosh, scanline tearing — while the studio's treatments are hue, saturation and contrast, which are operations on colour because colour is the subject. **This is a scope decision for the product owner, not something the audit should settle**; it needs scheduling or dropping rather than being left to read as work in progress

- [ ] 1a.4 **Decide whether `shader-editor` is still wanted.** Six requirements, none built. The product went the other way deliberately: source is assembled and copied *out* (`shader-delivery` R55) and never comes back. Editing a hook inside the studio and compiling it onto the canvas is the alternative to that, not a complement — one makes a shader editor, the other an instrument whose output is readable. **Owner's call**

- [ ] 1a.5 **Resolve the conflict between `lamellae-3d` and `viewInteraction: "non-spatial"`.** Eight requirements, none built, and one of them requires `mode: "orbit"` while the app declares `non-spatial` with a reason that is its direct negation. This is not a gap to fill quietly: building it makes a spatial product with a gizmo and model-presentation obligations, which is a different product from the one the other specs describe. Either schedule that or drop the file — leaving it means the specs hold a requirement the app is declared against. **Owner's call**

- [ ] 1a.6 **The flow cannot read the apply snapshot, so Restore could not move with the rest.** Everything that decides something moved out of the panel and into the dialog; restore was meant to go too and did not. `stack.applySnapshot` reads as `null` from a React selector inside the dialog while `onPanelAction` sees the same value without trouble — confirmed by instrumenting the dialog and reading the raw target. A restore rendered in the flow would be invisible exactly when an author needs it, so `Previous Stack` stayed as a panel row. Understand why the value does not reach the selector, then finish the move
